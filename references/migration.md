# 搬家、进度与还原

供 AI 执行搬家时读取。用户只确认搬什么、关闭指定软件、试用后确认是否正常，不选择复制方式或内部校验参数。主流程见 [SKILL.md](../SKILL.md)。

## 公开接口

统一调用 [scripts/move.ps1](../scripts/move.ps1)，不要调用旧 `migrate.ps1` 主体；后者仅提供复用函数。从原用户普通权限会话运行，让脚本按需请求 UAC；取消或换账户导致 `Failed` 时，解释原因并回到原账户，不绕过检查。

| 操作 | AI 调用 |
| --- | --- |
| 用户文件夹 | `move.ps1 -Kind KnownFolder -Folder Desktop\|Documents\|Downloads\|Pictures\|Videos -Destination <数据盘专用目录>`（Folder 取一个值） |
| 微信 / QQ | `move.ps1 -Kind WeChat\|QQ -Destination <数据盘专用目录>`（Kind 取一个值） |
| 查询进度 | `move.ps1 -Status -Id <记录Id>` |
| 按记录继续搬家 | `move.ps1 -ResumeId <记录Id>`；也可重跑原搬家指令，不换目标 |
| 释放本项原件 | `move.ps1 -ReleaseSource -Id <记录Id>` |
| 还原本项 | `move.ps1 -Rollback -Id <记录Id>`；始终指定 Id，避免影响其他项 |
| 演练 | 在对应操作上加 `-WhatIf`（PowerShell 通用参数）；不写文件、不启动后台任务或外部工具、不弹 UAC |

Id 为脚本返回的 32 位小写十六进制标识。查询、释放须带 `-Id`；还原始终带 Id，省略会处理多条记录。`-ResumeId` 只继续搬家，不与查询、释放或还原开关混用；后两者须重跑各自带 Id 的指令。

`-VerifyHash` 可在新搬家时启用 SHA-256 库存及复制校验，续传沿用记录中的设置；释放目标的试用变化判定仍按大小和时间。`-ResultPath` 只指定本次调用的结果文件，须为审计目录白名单允许且尚不存在的路径，不指定后台最终结果路径。AI 通常采用默认值，不让用户决策，也不手动传内部身份、提权或后台实现参数。

## 目标与顺序

从体检 `DataVolumes` 选择非系统盘、本地固定 NTFS 卷，剩余空间至少容纳该项并留 10% 余量。由 AI 决定盘符与专用空目录；已有其他内容时不清空，不合并覆盖。已有同一搬家记录的续传目标可复用。没有合适卷时先 [规划分区](partition.md)。

每次一个项目。先搬微信、QQ，再重新体检并处理文档等父文件夹，避免把聊天数据重复搬走。搬家脚本识别已移动项目，不能根据旧报告强搬。同盘分区只整理空间，不代替独立备份。

只处理系统登记的用户文件夹和能识别的聊天数据根；同步文件夹不处理。自定义聊天位置须能可靠识别，否则按 `Reason/Issues` 说明暂不搬家，不扩大白名单。默认位置以外的任意配置路径不能直接当聊天数据根。

## 后台执行和状态

搬家、释放和还原均默认在记录校验后启动独立后台进程，返回 `Running`；完整扫描、复制、切换或删除在后台进行，无需宿主专有任务功能。前置检查也可能直接返回其他状态。每条记录已有存活进程时，重复请求返回那次操作的 `Running`，不会同时启动新操作；核对 `Progress.Operation`，不能把它当作新请求已经执行。

1. 保存最初调用的参数、返回 `Id`、结果路径及操作类型（搬家 / 释放 / 还原）。聊天多数据根可能返回 `Items`；汇总状态取自某个子项，不代表全部完成，须保存每个子项的 Id、逐项处理并查询至结束。
2. 实际调用读 `RESULT:` 指向的 `pc-care/move/1` JSON。每次查询都会写新的结果文件；后台已写最终结果时，查询返回该最终结果内容，否则返回 `Running` 或 `Stalled`。
3. `Running` 按 `NextAction` 每 30 秒查询 `-Status -Id`。最终状态仍需核对 `StoppedAt/Reason` 和操作类型，不因工具调用返回就宣布完成。
4. 演练在 stdout 输出预览 JSON 和 `RESULT:`，但不会创建该结果文件；`Preview=true` 或 `StoppedAt=WhatIf` 均不能当成操作完成。

结果字段按以下含义读取；不要向用户展示原始 JSON、内部诊断或命令：

| 字段 | 含义与限制 |
| --- | --- |
| `Schema/GeneratedAt` | 结果模式为 `pc-care/move/1`，另有生成时间 |
| `Status/StoppedAt/Reason` | 状态、阶段和原因；阶段不是另一套 Status |
| `Id/Source/Destination` | 记录标识、源和目标；早期检查或未结束的状态查询可能只有 Id，路径为空 |
| `NextAction` | `Running` 提示每 30 秒查询；相关文件夹有未完成记录时也可能给续传指令，其他情况可为空 |
| `Progress` | 非最终状态可附带进度快照（`pc-care/move-status/1`），可能为 null；读 `Operation`（Move / Release / Rollback）、`Phase/FilesDone/BytesDone/TotalFiles/TotalBytes/LastUpdate`。总数初始可能为 0，文件数和字节数属于当前阶段或本次复制，可能重置，不能保证整体百分比或估计剩余时间；最终结果不保证有此字段 |
| `SkippedLinks` | 库存中跳过的非搬家记录链接数，默认 0；部分完成结果另有 `SkippedLinkDetails`，不把已保留的聊天搬家链接计入此数 |
| `ChangedAfterMove` | 释放校验接受的、大小或时间已变且修改时间晚于启用时刻的原文件数；不是新增文件数或变化字节数，无记录值时默认 0 |
| `MissingAtDestination` | 释放校验统计的目标缺失原文件数，无记录值时默认 0；不是字节数，也不单独证明校验通过 |
| `SourceKept` | 仅记录状态为 Released 时为 false，其他情况默认 true；缺少记录、还原后或部分释放失败时也可为 true，不能据此保证原件完整或计算腾出空间 |
| `ResumeHint` | 通用搬家续传提示，不随操作变化；释放和还原必须重跑各自指令，不照搬其中的 ResumeId 建议 |
| `Issues` | 聊天位置识别问题列表，可能为空；结合 Reason 翻译说明，成功也不意味着没有提示 |
| `Installations/IncludedChatData/Items/Preview` | 软件安装信息、包含的聊天类型、可选子项结果及演练标记；Items 须逐项检查 |

| 状态 | AI 下一步 |
| --- | --- |
| `Running` | 用 Progress 简述阶段和已处理数，继续查询；排队等待也不是失败；需搬的聊天软件保持退出 |
| `Stalled` | 进度记录缺失、后台进程不存活且没有最终结果，或相关文件夹仍有未完成操作；按 NextAction 优先完成相关记录，否则重跑原操作。搬家可用 ResumeId，释放或还原用各自带 Id 的指令；不换目标、不清空或新建第二项 |
| `NeedsAppExit` | 请用户正常退出 Reason 指明的软件，确认后重跑本次操作；搬家、释放、还原及包含聊天的文档均可能要求退出，绝不杀进程 |
| `NotEnoughSpace` | 解释目标空间不足；新搬家可另选数据盘，已有记录先腾出原目标空间后续传，不改目标或强行复制；空间不足也可能表现为 Failed，仍按 Reason 处理 |
| `AlreadyMoved` | 按 Reason 说明已在其他磁盘、已指向别处或已随其他记录搬家；不保证有本次记录，不重复搬家或宣称刚释放空间 |
| `Failed` | 解释 Reason/Issues，保留剩余原件、目标和记录；原因解决后续传，不强行删除或覆盖。释放失败可能已删部分原件，不能声称完整保留 |
| `Done` | 先排除演练；StoppedAt 为 Active 表示搬好待试用、原件保留，Released 表示原件已释放，RolledBack 表示已恢复原位置或尚未复制就取消（看 Reason）。还原保留目标数据且不自动合并试用后的修改；释放收益须另按实际空间变化确认 |

复制期间源数据变化时自动更新基线并补拷，每次执行最多 3 轮追赶；仍变化则 `Failed`，请用户暂时停止修改后续传。补拷会删除目标中源端已删除、且与旧基线大小、时间及已启用的哈希一致的副本，并清理相应目录；目标外来或已变文件会阻止继续，不能承诺目标副本永不删除。需搬的微信 / QQ 整个搬家阶段都须退出。

复制错误按 Reason 处理：占用（32/33）或无访问权限（5）请用户关闭相关软件；复制时移动或删除（2/3）请暂时停止更改文件夹；磁盘满（112）先腾空间，再重跑。原因可能附最多 5 个文件路径；不保证所有失败都能点名。若提示旧复制仍在运行，先等待，不强停或并发复制。

普通兼容链接或软件创建的链接不展开、不复制、不计数据量，计入 `SkippedLinks`，通常无需用户处理或手动删除。已由搬家记录核实的聊天链接会在新用户文件夹中恢复，继续指向原聊天目标，不重复搬聊天数据。

## 试用、释放与还原

搬家完成只表示新位置已启用，C 盘原件仍占空间。用户按平常方式打开聊天记录、编辑文档、下载文件，确认使用正常后，再明确同意释放原件，AI 才执行 ReleaseSource。释放也是后台操作，查询到最终结果后才报告完成。

释放时脚本会校验：

- 新位置仍在使用、数据盘在线，相关聊天软件已退出，记录有有效启用时刻 `ActiveAt`。目标原文件大小和修改时间均与基线一致则接受；任一变化时，仅修改时间晚于 ActiveAt 才接受并计入 `ChangedAfterMove`，数量不限；此判定不比较目标哈希。新增文件允许保留，不计入该数。
- 目标缺少的原文件数 **和** 字节数分别不超过原基线的 2%，数量返回 `MissingAtDestination`。超过任一限制就拒绝删除原件，解释“新位置少了很多文件，为了安全没有删除 C 盘上的原件”。不用让用户选容差或把正常编辑改回去。
- C 盘保留根的身份、文件和目录清单、文件大小与修改时间仍须吻合，启用哈希时也核对；续跑只允许缺少已释放项。多出文件时列出最多 5 个，其他变化不保证点名。文档内还有聊天搬家的保留原件时，须先经用户确认并释放那次聊天原件。链接只移除已核实未变的链接本身，不碰链接目标。

释放过程会周期性复核新位置是否仍有效、磁盘及软件退出状态；失败可能已经释放部分原件。尚未开始释放时若需恢复，运行指定 Id 的 Rollback，并查询到最终结果；若有包含聊天数据的文档搬家，先还原文档项，再还原聊天项。还原保留新位置的数据，不自动把试用后新增、修改的数据合并进旧副本；向用户解释这些新数据仍要保管。还原不会顺着跳过的链接触碰其他位置。

记录一旦进入 Releasing 或 Released 即拒绝自动还原，即使释放未完成也一样，已删部分不能靠还原找回。失败或中断只按记录及原操作续传，不自行重命名保留副本、不删除清单或库存文件，不通过手工递归删除绕过检查。
