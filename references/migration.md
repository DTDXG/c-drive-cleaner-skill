# 将数据迁移到 D 盘

目标是保留数据并改变存储位置。以下以 Windows 10 / Windows 11、本地固定 NTFS 的 D 盘为例；盘符、系统入口、客户端菜单及命令能力必须按实际版本核实。先读 [清理目标与禁止区](targets.md)，再选择迁移项。

公开入口为 `scripts/migrate.ps1 -Item UserFolder/DevCache/AppData/WSL/Junction`（斜杠表示可选值，不是合并传入的字符串）。所有迁移必须给 `-Destination`；先分别执行所选项的 `-WhatIf`，实际执行加 `-Confirm` 并逐步确认，不选择“全部是”。脚本没有阶段选择参数；以当前 `param` 与 `Get-Help .\scripts\migrate.ps1 -Full` 为准。本文还包含官方人工流程，`-WhatIf` 不能替随后手动输入的命令做演练；迁移演练不启动外部程序，不做写权限探测，不写配置、日志或清单。

| `-Item` | 参数与实际支持范围 |
| --- | --- |
| `UserFolder` | 必须给 `-Folder Desktop/Documents/Downloads/Pictures/Videos` 中一项；Known Folder 解析源，不接受 `-Source`。只复制校验，人工在“属性 → 位置”切换。 |
| `DevCache` | 必须给 `-Cache npm/pip/gradle/maven/conda` 中一项；仅配置切换时不传 `-Source`。复制旧数据须同时给 `-Source` 和 `-CopyExisting`，源仍须匹配迁移白名单。 |
| `AppData` | 必须给 `-App WeChat` 或 `-App QQ` 及 `-Source`；只复制当前 Documents Known Folder 下 `WeChat Files`、`Tencent Files`、`xwechat_files` 及其允许子项，再人工在应用内切换。 |
| `WSL` | 必须给准确的 `-Distro`，可给不同的 `-NewDistroName`，默认旧名加 `-Migrated`；从注册信息解析源，不接受 `-Source`。 |
| `Junction` | 必须给 `-Cache` 和白名单缓存 `-Source`，可给 `-ManifestPath`；先复制校验，再把源改名保留并登记联接。 |

`-VerifyHash` 用于普通复制逐文件 SHA-256，WSL 则额外记录导出归档 SHA-256、比对稳定文件集合摘要。只有联接回滚使用 `-Rollback`，可带 `-Source` / `-ManifestPath`，不能与 `-Item` / `-Destination` 混用。

## 所有迁移的共同门槛

1. **盘与空间**：确认 D 盘是非 C 盘、非 Windows 系统卷的本地固定 NTFS，健康、可写且长期在线；源与目标须在不同卷。脚本按复制字节数另留 `max(256 MiB, 5%)` 余量；WSL 初检按 `2 × max(1 GiB, 源目录逻辑大小)` 估算，再加余量，仍须为独立备份及后续增长留空间。源逻辑大小、实际占用、导出大小并不相等。D 盘若与 C 盘是同一物理盘，迁移不会增加整盘容量，也不是故障备份。
2. **路径与权限**：使用独立、明确、为空或不存在的目标目录，例如 `D:\UserData\<用户>\Documents`、`D:\DevCache\npm`，只改开发缓存配置时也要求空目标。不要把 D 盘根目录直接设成文档，不共用多个用户 / 多个已知文件夹的同一目标。拒绝源目标相同、相互包含、经过重解析点或落入禁止区的路径；目标位置必须通过当前脚本的白名单与安全校验。确认原用户可访问，其他普通用户不会因继承宽泛权限读到私密数据。
3. **状态与备份**：记录原用户、源路径、目标路径、工具版本、旧配置、文件数、大小、关键文件摘要与应用验证点。敏感配置和备份不写入公共日志。对不可再生数据先有经过验证的独立备份；“C 盘源数据仍在”仅是暂存退路。
4. **停止写入**：退出应用、托盘程序、下载与构建任务；按需要正常停止服务或发行版，并记下原状态。脚本检查相关进程，发现仍运行则停止，不强杀。更新、同步、加密或企业策略阻止迁移时停止，不能抢夺所有权；脚本不支持向非空预复制目标增量续传，中断后的目标保留供人工核查。
5. **复制与校验**：普通复制使用 `robocopy /E /COPY:DAT /R:1 /W:1 /XJ`，不移动、不删除源数据；不用 `/MIR`、`/PURGE`、`/MOVE`。扫描有未知 / 跳过项时停止，不把重解析点排除后仍声称完整。对比复制前后源的相对路径、文件数、目录数、字节数及文件长度 / 修改时间，再比对目标；可加 `-VerifyHash` 校验 SHA-256。数据库须在应用关闭后的稳定副本上校验。Robocopy 0–7 仍需通过上述校验，8 及以上失败；不能只凭退出码切换。
6. **切换与试用**：通过官方设置、工具配置或明确支持的机制切换；每一步展示结果并等待用户确认后继续。重启应用、必要时重启 Windows，验证新旧数据和新写入落点。出现错误立即停止下一步，不在两份数据上交替写入。
7. **释放源空间**：经过实际试用、确认独立备份可恢复后，才单独提出删除旧源副本。旧源一旦删除就不再有快速原地回滚；日志不含数据，不能用于恢复。涉及用户数据的源文件不属于缓存清理授权，不能顺带用清理脚本删除。记录最终 C 盘可用空间及保留备份位置。

复制必须保留应用所需属性；不能笼统假定跨卷后 ACL、EFS、备用数据流、压缩 / 稀疏属性、硬链接关系都会保留。对 EFS 加密文件先验证解密及证书备份；不要盲目套用 `/COPYALL` 导入不适合目标的权限。云占位文件需先用客户端确认本地完整性及云端状态；复制可能触发下载，不能按占位大小估算空间。

迁移须在原用户账户运行，脚本核对当前令牌 SID 等于共享上下文的原 SID；已提供的 SID / 目录须成对并与 ProfileList 匹配，路径也须安全。共享库的跨账户验证要求显式成对参数、ProfileList 匹配，且 Explorer 的所有者 SID 为原 SID、SessionId 与当前进程相同且大于 0；无法核实则不验证通过，环境变量不能单独证明跨账户身份。`migrate.ps1` 没有 `-OriginalUserSid` / `-OriginalUserProfile` 参数，也不支持借另一管理员账户迁移；这两个入口参数仅由 `clean-system.ps1` 提供。同账户可成对传递 `CLEANER_ORIGINAL_USER_SID` / `CLEANER_ORIGINAL_USER_PROFILE` 环境变量，不能拼接缺失的显式参数。

普通复制在启动 robocopy 前，通过共享库取得源、目标根及全部祖先的保护句柄，以 `OPEN_REPARSE_POINT` 打开且不共享 DELETE；任一级获取失败就停止。实际复制及随后源 / 目标校验期间持续持有这些句柄，复制后、校验后重新检查目标路径；异常阻止切换，`finally` 释放已取得的句柄。`.cdrive-copy-guard` 只是将根纳入保护的虚拟子路径，不会创建对应文件。

**仍有残余风险**：robocopy 按路径访问子项，`/XJ` 和根 / 祖先句柄未完全消除子项在复制期间被其他进程并发替换的风险，也不冻结文件内容；后续校验不能使整个过程成为原子快照。须关闭相关应用、构建及同步进程，并限制其他进程对两端目录的写权限。真实 NTFS 句柄行为与 PowerShell 5.1 运行仍需 Windows 实测，Linux 模拟逻辑验证不代表已消除此风险。

## UserFolder：桌面、文档、下载、图片、视频

入口：`migrate.ps1 -Item UserFolder`。这是已知文件夹迁移，不是整棵用户配置文件迁移。

**步骤**

1. 在资源管理器确认文件夹实际位置及“属性 → 位置”是否可用。已启用 OneDrive 文件夹备份、企业文件夹重定向或组策略时，先核实对应官方流程；不能直接修改其本地目录、停同步后强行搬走。
2. 为每个文件夹建独立目标，例如 `D:\UserData\张三\Documents`，不选 D 盘根目录，也不选另一个已知文件夹。关闭使用该目录的应用，按共同流程备份、复制与校验。
3. 等脚本复制校验通过后，使用该文件夹“属性 → 位置 → 移动”选择目标。系统再次询问是否移动原文件时选择“否”，保留旧副本；先核实最终完整路径，不合并 / 覆盖未知内容。不要凭同名目录判断成功。
4. 一次只迁移一个文件夹。没有“位置”页或受策略管理时，停在诊断与建议，不直接改注册表代替。

**验证**

- “位置”页和 Windows 已知文件夹解析结果均指向 D 盘，快速访问、应用“保存到文档”等入口实际落到新位置。
- 原文件数量、关键文件摘要和可打开性匹配；新建一个用户同意的测试文件，确认出现在 D 盘。注销 / 登录后再检查，测试文件按正常流程处理。
- 云端与本地状态没有意外删除、重复同步或重新下载。对受保护目录，客户端“备份已完成”仍需按其功能核实。

**回滚**

关闭相关应用，确认 C 盘能容纳最新数据；先保留 D 盘新产生的内容，再通过“位置 → 还原默认值 / 移动”返回原位置。对同名冲突先人工比对，不能用旧源覆盖最新文件。完成相同验证后才考虑删除 D 盘副本。

**常见坑**

- 将多个文件夹指向同一个目录会混合内容；直接拖动“文档”目录不一定改变已知文件夹注册位置。
- 软件可能硬编码旧路径，迁移后需检查该软件的保存设置；不能因此给整个用户目录加联接。
- 桌面迁移仅针对该用户，不包括公共桌面、开始菜单、浏览器配置或整个 `%USERPROFILE%`。

“设置 → 系统 → 存储 → 高级存储设置 / 更改新内容的保存位置”（名称依版本）只影响支持该机制的新内容，不会统一搬走现有文件或传统桌面程序。不能把改默认盘符算作迁移完成。

## DevCache：开发缓存与工具配置

入口：`migrate.ps1 -Item DevCache -Cache <工具> -Destination <目标>`，支持 npm、pip、gradle、maven、conda。只改配置时不提供 `-Source`；复制旧数据必须同时给 `-Source` / `-CopyExisting`。真实源由用户先查询，并须通过 `DevCacheMigration` 白名单；除共享缓存根外，仅迁移类别允许完整 `.gradle` 用户目录和 `.m2\repository`，不授权删除。NuGet 仅有下表人工配置指引，没有 `-Cache NuGet`。迁移与清理是两个动作，不顺带删除缓存、环境、凭据或本地工件。

清理入口的 `clean-cache.ps1 -Category DevCache` 实际执行时会先查询 npm / pip / conda / dotnet NuGet 实际路径、核对 NuGet 环境覆盖并逐项验证；任一失败跳过整个工具，非 C 盘新缓存也不会自动获得清理授权。工具执行及后置校验期间逐路径持有祖先防替换句柄，运行前后复查路径，`finally` 释放句柄；祖先缺失或获取句柄失败则跳过整个工具。为允许官方工具删除缓存根，不锁根本身，根及子项仍有并发替换风险。它不受 `-MinAgeHours`（默认 24，范围 `0..876000`）约束；其 `-WhatIf` 不启动开发工具，仅报告计划查询和清理的命令，路径标为“待解析”，不执行查询或清理、不写审计日志。不要把清理入口的自动查询行为套到迁移 `-Source` 上。

**步骤**

1. 选择具体工具、解释器、账户和配置层级。列出命令行参数、项目配置、用户 / 系统环境变量的覆盖关系，记录有效旧值；不要在日志中输出 token 或密码。
2. 停止 IDE、守护进程、构建与包安装。按共同流程复制所需数据至该工具专用目标并校验；不把多个包管理器放入同一平铺目录。
3. 在对应工具支持的配置层切换路径。脚本修改 npm 的原用户 `.npmrc`、Maven 的 `.m2\settings.xml`、conda 的 `.condarc`，已有文件先备份为 `.cdrive-backup-<ID>`；pip / Gradle 修改用户及当前进程环境变量，旧用户值先写入审计记录，写日志失败则不修改。conda 只把新 `pkgs_dirs` 前置，保留旧路径为后备。下表也包含人工方式示例，须按版本核实；配置后从新终端 / 新进程验证，必要时重启 IDE 或服务。
4. 完成一次实际依赖恢复 / 构建，确认配置与新写入都使用 D 盘，保留旧源至试用结束。

| 工具 | 查询 / 切换方式示例 | 必须注意 |
| --- | --- | --- |
| npm | `npm config get cache`；`npm config set cache "D:\DevCache\npm"` | 项目或环境变量可能覆盖用户设置；这是缓存，不是全局包 `prefix`，不顺带改全局安装目录。 |
| pip | `python -m pip cache dir`；为正确用户配置 `PIP_CACHE_DIR=D:\DevCache\pip` | 对每个实际使用的解释器查询；不搬 `site-packages` 或虚拟环境。持久环境变量采用受支持接口并保留旧值，不用可能截断值的通用拼接命令。 |
| Gradle | 为相应用户配置 `GRADLE_USER_HOME=D:\DevCache\gradle` | 原目录含 `gradle.properties`、`init.d`、wrapper 等，不止缓存；需按所需内容复制并保护凭据。迁移前停止 Gradle daemon，`--gradle-user-home` 等可能覆盖环境变量。 |
| Maven | 在有效 `settings.xml` 中设置 `<localRepository>D:\DevCache\maven-repository</localRepository>` | 备份并正确编辑现有 XML；不覆盖 mirrors、servers 等配置，不把含凭据的 `settings.xml` 当缓存删除。保留只存在本地的 `install` 工件；`-Dmaven.repo.local` 可能覆盖配置。 |
| conda | 查询 `conda config --show pkgs_dirs`，用受支持配置将 `pkgs_dirs` 指向 D 盘 | 包缓存与 `envs_dirs` 不同；跨卷通常不能硬链接，环境可能改用复制而增大总体占用。已有环境不能直接搬路径，迁移环境应导出配置后重建并验证。旧缓存可能仍被链接使用，确认前不删。 |
| NuGet | `dotnet nuget locals all --list`；全局包可用 `NUGET_PACKAGES` 或有效 NuGet.Config 的 `globalPackagesFolder` 配置 | 各 locals 并非同一目录；`globalPackagesFolder` 主要针对 PackageReference，旧式 `packages.config` / `repositoryPath` 要按项目类型核实。HTTP、插件等缓存需按工具版本分别核实支持的设置。 |

**验证**

分别从新终端、IDE 和实际构建账户查询有效目录；执行一个代表性项目的依赖恢复与构建，检查 D 盘产生缓存、旧 C 盘目录不再增长。验证离线项目、本地 Maven 工件、私有包源认证、Gradle 初始化脚本仍可用。只看到目录存在不算验证成功。

**回滚**

停止工具，备份 D 盘迁移后的新增本地产物，恢复原配置文件与环境变量的原值 / 原先未设置状态；新开进程验证。若需复制回去，按共同流程校验且禁止镜像删除。旧源不完整时从已验证备份恢复，不能默认重新下载就能找回所有依赖。

**常见坑**

- `setx` 不改变当前进程；管理员用户、服务用户、IDE 内终端可能各自使用不同配置。
- 迁移完整 Gradle 用户目录与“删除 `.gradle`”不是同一操作；Maven 仓库也可能含不可再下载的内容。
- conda 环境、Python venv、Node 全局程序常有绝对路径；不能套用纯缓存迁移流程。
- D 盘杀毒、权限、磁盘性能或跨卷复制可能降低构建速度；不要为速度关闭安全软件或扩大 ACL。

## AppData：应用内存储迁移

入口：`migrate.ps1 -Item AppData -App WeChat/QQ -Source <旧目录> -Destination <目标>`（App 二选一）。仅支持当前 Documents Known Folder 下的 `WeChat Files`、`Tencent Files`、`xwechat_files` 及允许子项；其他自定义数据根、AppData 内聊天库及其他应用不因本文示例获得脚本复制授权。**禁止整体移动 AppData / ProgramData，也不修改用户配置文件根路径。** 常见软件定位线索见 [targets.md](targets.md)。

**步骤**

1. 在当前版本应用中查询“文件存储 / 下载目录 / 缓存 / 数据迁移”的具体能力；区分下载保存路径、缓存路径、聊天库与附件路径。只改下载路径通常不影响历史数据。
2. 对聊天软件、网盘、笔记与办公软件，先确认没有待发送、待上传、未同步或未完成的任务。云端有聊天记录不代表附件、离线文档和完整历史可恢复。
3. 用应用自带备份 / 导出功能保护不可再生数据；正常退出后再复制、校验。若内置迁移要求应用运行，按其官方向导操作，源数据的备份在迁移前完成；不要在应用写数据库时直接文件复制。
4. 脚本复制校验通过后，使用应用内更改存储位置；核对软件是否自动追加目录名，最终路径必须与 `-Destination` 完全一致。不要选择会删除旧文件的移动选项；若应用强制移动并删旧源，先取消切换，保留副本供人工核查。只影响新数据时，按版本支持的导入流程补齐历史；没有明确流程则停在建议，不猜目录、不改私有数据库。
5. 保留源副本，重新登录与试用；不能将目标目录存在或设置保存成功当成历史已迁移。

**验证**

检查多个时间段的聊天记录、原图 / 原视频、接收文件、离线文档、下载任务与搜索；打开一份旧附件，再收发或下载一份新内容，确认新文件实际位于 D 盘。多账户逐个验证。重启应用后，原 C 盘目录不应继续积累相同大文件；少量配置仍在 C 盘属于正常情况。

**回滚**

正常退出应用，先保存 D 盘新增内容，再用应用设置 / 原生还原流程改回原路径或从备份恢复。数据库不能简单合并；发生双边写入时先选择完整主副本，并用软件支持的导入方法合并历史。验证后再处理重复副本。

**常见坑**

- 修改设置不搬历史文件，升级又改变了真实路径，多个账号使用不同数据根。
- Windows DPAPI、应用加密或账号绑定可能使复制后的数据库无法单独恢复；文件摘要一致不能代替应用内验证。
- 同步软件中移动 / 删除本地文件可能传播至云端；先确认其官方迁移与选择性同步行为。不能把“退出客户端”当成禁止未来同步删除的保证。
- 绿色版、商店版和企业定制版不能共用固定目录假设；厂商不支持时不要用整棵 AppData 联接兜底。

## WSL：导出后用新名字导入

入口：`migrate.ps1 -Item WSL`。高风险操作；先确认 WSL 功能、发行版类型和备份空间。使用系统内置版还是 Store WSL、是否支持 `--manage` / `--move` / 稀疏回收等，必须查询当前 `wsl --help` 与实际版本；旧版可能没有 `wsl --version`。本流程以可用的 `--export` / `--import` 为基础，不要求新命令。

脚本的 `-Distro` 须与当前用户 Lxss 注册记录名称及大小写一致；新名称须不同，首字符为字母或数字，其余仅字母、数字、点、下划线、连字符，最长 80 字符。默认旧名加 `-Migrated` 仍须符合此规则，含中文等字符的旧名称须显式指定合规 `-NewDistroName`。目标目录初始为空或不存在，脚本在其中保留 `<新名>-export.tar` 和新发行版安装目录；不接受 Docker 托管的内部发行版。

执行时脚本先启动旧发行版读取默认 Linux 用户和稳定文件集合，然后仅终止所选旧发行版、导出，再以原 WSL 1 / 2 类型新名导入并启动校验；不改默认发行版、不自动改默认 Linux 用户、不执行注销。稳定集合排除 `/proc`、`/sys`、`/dev`、`/run`、`/mnt`、临时目录、日志及部分自动生成的主机配置，不能代替业务验证。下列 `--shutdown`、默认项切换等是额外的人工步骤，须另行核实影响。

列表、终止、导出 / 导入管理命令经 `Invoke-External -OutputEncoding` 显式按 UTF-16LE 解码 stdout / stderr，保留 NUL 清理；Linux `--exec` 输出维持默认解码。该编码参数属于共享函数，不是 `migrate.ps1` 的入口选项。中文输出、真实 WSL 行为及 PowerShell 5.1 仍需 Windows 实测。

**步骤**

1. 用 `wsl --list --verbose` 记录准确发行版名字、默认项、WSL 1 / 2 类型；若此查询不可用，先按实际版本确认替代查询方法。记录默认 Linux 用户、UID/GID、`/etc/wsl.conf`、重要挂载、服务、端口以及 Windows 侧集成设置。
2. 在 Linux 内停止数据库、容器及写入任务并正常退出；必要时为应用做一致性备份。正常退出 Docker Desktop 后用 `wsl --shutdown` 停止 WSL；这会影响所有发行版，事先确认。不要把 Docker 内部托管的发行版套用成普通用户发行版。
3. 导出到受保护且空间充足的位置。下面以已存在的示例发行版 `Ubuntu`、已准备的备份目录为例，名称与路径必须替换为实际值：

   ```powershell
   wsl --export "Ubuntu" "D:\WSLBackup\Ubuntu.tar"
   ```

   检查退出码、导出文件大小和可读取性，保存摘要；保留重要数据的独立备份。导出不包含 `/mnt/c`、其他外部挂载的数据，也不备份 Windows 全局 `.wslconfig`、终端配置或宿主的凭据文件。
4. 用**不同名字**和新的专用安装目录导入，不覆盖原发行版。下面的 `--version 2` 仅适用于已确认采用 WSL 2 的情形；WSL 1 应按实际类型选择，不能顺带隐式转换：

   ```powershell
   wsl --import "Ubuntu-D" "D:\WSL\Ubuntu-D" "D:\WSLBackup\Ubuntu.tar" --version 2
   ```

5. 用 `wsl -d "Ubuntu-D"` 进入并执行下述验证。导入后常默认以 root 启动；用 `wsl -d "Ubuntu-D" -u <原用户名>` 验证原用户存在，再按该版本支持方式配置默认用户，例如保留原配置并调整 `/etc/wsl.conf` 的 `[user] default=<原用户名>`。配置生效可能需要终止该发行版后重启；不要覆盖其他配置段。导入发行版通常没有对应商店启动器的 `config --default-user` 接口。
6. 验证通过后，按需用 `wsl --set-default "Ubuntu-D"` 改默认项，更新 Windows Terminal、VS Code Remote WSL、计划任务与引用旧发行版名的脚本；继续保留原发行版但避免双边写入。
7. 经过试用并确认备份可恢复后，才单独确认是否注销旧发行版。`wsl --unregister "Ubuntu"` 会删除旧发行版注册及其关联数据，**不是移除一个快捷方式**；必须精确核对名字。未执行注销 / 受支持的旧安装清理前，C 盘原虚拟磁盘仍占空间，不能宣称已释放。

**验证**

- 新发行版列为预期 WSL 类型，安装位置在 D 盘；原 Linux 用户、UID/GID、权限、关键文件摘要和项目一致。
- 检查数据库、包管理器、开发构建、SSH 配置、网络、DNS、端口转发、systemd（如已启用）及自动挂载。使用该发行版的 Docker 集成需按 Docker 当前版本重新确认。
- 以默认方式进入时身份正确；重新启动 Windows 后再次验证。文件数量相同不足以覆盖数据库一致性与服务可用性。

**回滚**

旧发行版仍在时：停止新发行版的写入，备份其新增数据，通过明确的应用导出 / 文件校验流程迁回需要保留的变更，然后恢复旧默认项与外部集成。旧发行版已注销时：只能从已验证导出文件导入新的专用目录，再恢复用户名、默认项与集成；备份之后产生的数据需另有备份。不要为回滚直接覆盖 `.vhdx` 或先注销当前唯一可用副本。

**常见坑**

- 只关闭终端并不会停止后台数据库或所有 WSL 进程；导出和复制必须获得一致状态。
- 更换发行版名称会改变 `\\wsl$\<名称>` 等路径，Windows 侧工具不会全部自动更新。
- 导入可能不保留商店应用关联及原默认用户；WSL 功能受系统、内核和 Store 组件版本共同影响。
- 导出文件与目标虚拟磁盘同时存在，峰值空间可能超过预期。NTFS 压缩、EFS、网络盘和同步目录不作为本方案的 VHDX 目标。

## Junction：仅缓存目录的最后手段

入口：`migrate.ps1 -Item Junction`。仅用于白名单明确允许、没有官方迁移机制的具体缓存目录。不能用于系统目录、整个用户目录、AppData、ProgramData、应用数据库、同步目录或 `.vhdx`。要求本地 NTFS，源及目标在切换前均不是重解析点，路径父级安全。

必须给 `-Cache` 和 `-Source`，`-Cache` 选项与 DevCache 相同，但源路径仍只由共享缓存白名单授权；选择 Maven 等名称不自动授权其整个目录。默认清单为共享日志同目录的 `junctions.json`；`-ManifestPath` 只能选共享上下文审计目录内认可的 JSON 文件，不能放进源、目标或保留缓存目录。

**步骤**

1. 明确该缓存可重建，确认软件允许此布局、不是安装 / 更新关键路径；记录原路径、目标、软件版本与回滚副本。先尝试官方缓存配置。
2. 停止所有相关进程。将缓存复制到独立目标并校验；将原缓存保留为明确命名的回滚副本。原路径腾空前检查是否有未复制数据，不能递归清空来“解决冲突”。
3. 脚本取得清单锁并逐阶段写 `Prepared` / `SourceRetained` / `Active`，源保留名为 `<原路径>.cdrive-retained-<32位ID>`；原路径不存在时才创建目录联接。语法为 `mklink /J "<原路径>" "<D盘目标>"`，`mklink` 是 **cmd.exe 内建命令**，实际调用由共享 `ShouldProcess` 包装。空格、中文路径须正确引用，脚本拒绝含 `%!^&|<>()"` 等 cmd 元字符的路径，不能靠加引号放行。
4. 核对新建对象是预期的目录联接、目标完全匹配，写入权限符合原用户要求；记录联接清单后再启动应用。

**验证**

检查联接对象本身的类型和目标；通过应用产生一份测试缓存，确认内容实际写入 D 盘。重启应用并检查更新器是否保留联接、是否在旧路径旁另建真实目录。迁移后的常规扫描应单列联接，缓存删除应拒绝跟随联接；不能为了继续清理而放宽共享安全检查。

**回滚**

先用 `migrate.ps1 -Rollback -Source "<原路径>" -WhatIf` 演练，确认后实际执行；可用 `-ManifestPath` 选择清单。省略 `-Source` 会选择所有未回滚 / 未取消记录。脚本验证清单版本、所属 SID、路径、联接类型与目标，并在确认后持锁重读；记录变动则停止，不与 `-Item` / `-Destination` 混用。

1. 停止应用，核实原路径仍是此次记录的联接且目标匹配；类型改变或记录不符就停止。
2. **只删除联接本身，不递归、不遍历目标**。脚本使用 `.NET Directory.Delete(联接路径, false)`；人工核验后可使用 cmd 的 `rmdir "<联接路径>"`，不加 `/S`，严禁误把 D 盘目标路径传入。不把通用递归删除用于联接。
3. 恢复保留的原真实目录；若要保留 D 盘新增缓存，先在停止状态复制、校验。验证应用改回 C 盘写入后，目标副本另行处理，不随联接一起删除。

**常见坑**

- `mklink /J` 与符号链接不是同一类型，不能泛化符号链接的权限或开发者模式规则。
- 应用更新器、备份软件与扫描器可能错误处理联接；复制工具也可能沿联接扩大范围。
- D 盘缺失或改盘符会使原路径失效；移动缓存后，安全白名单并不自动扩展到 D 盘。
- 清单写入使用临时文件并原子替换，事务持有 `.lock`；中断遗留锁只能在确认没有迁移进程后人工处理。保留目录缺失时，回滚可能只移除联接并警告，不保证能恢复原目录，更不会删除目标数据。

## 游戏、大型软件和 Docker Desktop

这些是官方工具优先的配套流程，并不是额外的 `-Item Game` / `-Item Docker` 参数；脚本无明确支持时执行人工指引。

| 对象 | 步骤 | 验证 | 回滚与常见坑 |
| --- | --- | --- | --- |
| Steam | 备份非云存档、截图、模组；通过设置“存储”添加 D 盘库，再移动选中游戏。旧版菜单位置需核实 | 客户端显示新位置；校验游戏文件；启动并加载已有存档、模组 | 用客户端移回或重新安装并恢复存档。云存档不覆盖所有游戏；`userdata` 与文档 / AppData 存档不一定随库移动。 |
| WeGame / Epic / Xbox 等 | 优先客户端 / Windows 支持的“移动”；不支持时备份存档与安装信息，再正常卸载重装到 D 盘，按厂商流程识别现有文件 | 启动器识别、更新、启动、反作弊与存档均正常 | 用同一官方流程移回或重装并恢复备份；不能把 Steam 的搬目录方法套到其他客户端，不改 WindowsApps 权限。 |

| Docker Desktop | 先核实版本与后端；正常停止容器，备份卷中的业务数据与必要镜像，退出 Docker；用当前版本设置中的磁盘映像位置迁移功能（若存在），按要求停止 WSL 并迁移 | 启动后检查后端、镜像、容器、卷、应用数据、绑定挂载及磁盘实际位置 | 优先设置内移回或按同版本官方备份恢复；不同版本可能没有 `docker-desktop-data`，不能对内部发行版盲目 export / unregister。绑定挂载在外部 Windows 路径的数据不会随磁盘映像一起移动。 |

## WSL / Docker 虚拟磁盘压缩：独立维护项

压缩是收回虚拟磁盘内已空闲的宿主空间，不是迁移，也不能代替备份。无额外 `-Item`；脚本未实现时仅给建议。

**步骤**

1. 确认当前 WSL / Docker 版本是否支持自动稀疏回收及其条件。动态 VHDX 的容量上限、内部已用量、宿主文件长度、实际占用是不同指标，不能相互替代。
2. 在来宾系统内用其受支持的方式清理确实可删数据并 trim，检查结果；不要填满磁盘写零。Docker 卷是业务数据，不能通过 `prune --volumes` 替代 trim。
3. 正常停数据库、容器和 Docker Desktop，`wsl --shutdown`，确认对应虚拟磁盘已不被占用；制作离线且验证可读的备份。
4. 核实磁盘类型及工具要求。`Optimize-VHD` 需要可用的 Hyper-V PowerShell 模块，系统版本 / 可选组件未必提供；不能假定 Windows Home 或 PowerShell 7 中可用。DiskPart `compact vdisk` 需选中正确的动态扩展虚拟磁盘，且磁盘必须已卸载或只读附加；逐步核对完整路径，不对仍读写挂载的磁盘操作。不提供绕过占用或强制卸载的数据破坏方案。
5. 压缩后启动原环境，比较宿主实际占用与卷可用空间，完成发行版 / 容器 / 业务验证。空间不回收时先核实 trim、文件系统与版本支持，不删除 `.vhdx` 重试。

**回滚与坑**

压缩通常没有“撤销”按钮；磁盘损坏只能在环境停止且明确恢复步骤后用离线备份恢复。恢复旧映像会丢失备份后的变更。稀疏标志与压缩工具的兼容条件随 WSL、Windows 版本而异，必须按实际版本核实；不要随意切换磁盘标志、附加写入或对 Docker 管理的磁盘使用未经支持的流程。

## 中断、空间不足或验证失败

未切换前中断：保持原配置与原数据，标记目标为未完成，不删除源。已切换但未清源：停止新写入，记录两端差异，按该项回滚流程恢复；不得拿旧副本直接覆盖新数据。已注销 WSL 或删除源后：只可从经过验证的备份恢复，不再承诺原地撤销。

空间不足、访问失败、版本不支持、目标路径变成重解析点或校验不符时，停止当前项，保留证据与副本并报告失败。不要扩大权限、跳过校验、清空目标或执行镜像删除来强行继续。
