# 搬家、进度与还原

供 AI 执行搬家时读取。用户只确认搬什么、关闭指定软件、试用后确认是否正常，不选择复制方式或内部校验参数。主流程见 [SKILL.md](../SKILL.md)。

## 合入状态与公开接口

当前文档分支没有 `scripts/move.ps1`。以下现有参数核对自 v1/move 的该脚本；后台执行、`-Status`、`NextAction`、`SkippedLinks`、`ChangedAfterMove`、`MissingAtDestination` 和补拷规则来自该分支正在完成的修复任务，**待 v1/move 合入并验证**。不要在入口缺失时调用旧的 `migrate.ps1` 主体替代；它仅是新入口复用的函数来源。

| 操作 | AI 调用 |
| --- | --- |
| 用户文件夹 | `move.ps1 -Kind KnownFolder -Folder Desktop\|Documents\|Downloads\|Pictures\|Videos -Destination <数据盘专用目录>`（Folder 取一个值） |
| 微信 / QQ | `move.ps1 -Kind WeChat\|QQ -Destination <数据盘专用目录>`（Kind 取一个值） |
| 查询进度（待合入） | `move.ps1 -Status -Id <记录Id>` |
| 按记录继续搬家 | `move.ps1 -ResumeId <记录Id>`；通常重跑原指令即可，不换目标 |
| 释放本项原件 | `move.ps1 -ReleaseSource -Id <记录Id>` |
| 还原本项 | `move.ps1 -Rollback -Id <记录Id>`；始终指定 Id，避免影响其他项 |
| 演练 | 在对应操作上加 `-WhatIf`；不写记录、不启动后台任务或外部工具 |

`-VerifyHash` 可请求文件内容校验；`-ResultPath` 可选新结果文件路径。AI 通常采用默认值，不让用户决策。不要手动传内部身份、提权或 worker 参数。

## 目标与顺序

从体检 `DataVolumes` 选择非系统盘、本地固定 NTFS 卷，剩余空间至少容纳该项并留 10% 余量。由 AI 决定盘符与专用空目录；已有其他内容时不清空，不合并覆盖。已有同一搬家记录的续传目标可复用。没有合适卷时先 [规划分区](partition.md)。

每次一个项目。先搬微信、QQ，再重新体检并处理文档等父文件夹，避免把聊天数据重复搬走。搬家脚本识别已移动项目，不能根据旧报告强搬。同盘分区只整理空间，不代替独立备份。

只处理系统登记的用户文件夹和能识别的聊天数据根；同步文件夹不处理。不能辨认的自定义聊天位置仅提示“找到了自定义的聊天文件位置，但无法确认，暂不搬家”，不扩大白名单。默认位置以外的任意配置路径不能直接当聊天数据根。

## 后台执行和状态（待合入）

实际请求只做快速检查、创建或复用记录，启动同用户的独立后台进程后立即返回。无需宿主专有任务功能。一次记录只允许一个工作进程；重复启动在其存活时返回 Running，不产生第二份操作。

1. 保存最初调用的参数、返回 `Id`、结果路径及操作类型（搬家 / 释放 / 还原）。有 `Items` 时保留每个子项的 Id，不用汇总项替代所有记录。
2. 读每次 `RESULT:` 行和 `pc-care/move/1` JSON；按 `NextAction` 指示，通常每 30 秒查询 `-Status -Id`。
3. `Running`：向用户简短报告阶段、文件数 / 字节进度，继续查询。不要因一个工具调用返回而宣布搬家结束。
4. `Stalled`：工作进程中断且无最终结果，重跑同一操作续传；保留原目标、清单和副本。仅重复被中断的阶段，不清空后重来。
5. 最终状态还要看 `StoppedAt` 和 `Reason`。`Done` 是当前操作完成，释放和还原完成不能说成刚搬完。

保留现有结果的 `Schema/GeneratedAt/Status/StoppedAt/Reason/Id/Source/Destination/SourceKept`；`Installations/IncludedChatData/Items` 可能提供聊天适配或子项信息。`ResumeHint` 为续传线索。最终结果路径以实际返回为准；不要展示内部诊断或原始 JSON。

| 状态 | AI 下一步 |
| --- | --- |
| `NeedsAppExit` | 请用户正常退出 Reason 指明的软件，确认后重跑；绝不自动杀进程 |
| `NotEnoughSpace` | 解释目标空间不足，选择合适数据盘或先清理；不强行复制 |
| `AlreadyMoved` | 核对这项已完成的记录和原件是否保留，不重复搬家或宣称刚释放空间 |
| `Failed` | 解释 Reason，保留两端；文件占用时请用户关闭相关软件再续传，不清空目标重试 |
| `Done`（搬家） | 请用户正常使用软件或文件夹一段时间，原件仍保留 |
| `Done`（释放） | 原件释放完成，按实际空间变化解释收益；已删部分不能还原 |
| `Done`（还原） | 已恢复原位置，新位置的副本和搬家后产生的数据仍需保管 |

复制只增量补拷、不镜像清空目标。复制期间源数据变化时自动更新基线并补拷，最多 3 轮；仍在变化就停止，请用户暂时不要修改该文件夹，再重跑原操作。微信 / QQ 整个搬家阶段都须退出。

普通系统兼容链接或软件创建的链接不展开、不复制、不计数据量，返回 `SkippedLinks`（计数，另有内部明细）。这是正常现象，无需用户处理或手动删除链接。

## 试用、释放与还原（新释放规则待合入）

搬家完成只表示新位置已启用，C 盘原件仍占空间。用户按平常方式打开聊天记录、编辑文档、下载文件，确认使用正常后，再明确同意释放原件，AI 才执行 ReleaseSource。释放也是后台操作，查询到最终结果后才报告完成。

释放时脚本会校验：

- 新位置仍在使用、数据盘在线；每个原文件在目标位置大小和修改时间一致，或者修改时间晚于启用时刻 `ActiveAt`（正常试用后的修改）。新增文件允许保留，修改数量返回 `ChangedAfterMove`。
- 目标缺少的原文件数 **和** 字节数分别不超过原基线的 2%，数量返回 `MissingAtDestination`。超过任一限制就拒绝删除原件，解释“新位置少了很多文件，为了安全没有删除 C 盘上的原件”。不用让用户选容差或把正常编辑改回去。
- C 盘保留原件的身份和内容仍须严格吻合。多出文件或原件变化时拒绝释放，并点明相关文件（最多 5 个），AI 不自行删除或覆盖。系统链接释放时只移除已核实未变的链接本身，不碰链接目标。

释放前若需恢复，运行指定 Id 的 Rollback，并按状态查询。还原保留新位置的数据，不自动把试用后新增、修改的数据合并进旧副本；向用户解释这些新数据仍要保管。还原不会顺着跳过的链接触碰其他位置。

释放已删掉的部分不能靠还原找回。失败或中断只按记录续传，不自行重命名保留副本、不删除清单或库存文件，不通过手工递归删除绕过检查。
